The Challenge: DynamoDB 1KB Boundary & Batch Throttling

1KB WCU vs 4KB RCU boundary, verbose TupleKey schema & batch-write scaling limits
Part 2: The Challenge
The 1KB WCU Boundary Bottleneck

Okta Fine-Grained Authorization (OpenFGA / ReBAC) stored ~2B relationship tuples (~2 TB). Verbose schema attribute names (relation, condition) pushed P90 record sizes to ~1.05 KB:

  • RCU Boundary (4 KB): System ran ~10,000 read TPS (~50% DAX cached). At 1.05 KB, reads cost exactly 1 RCU (shrinking saved $0 on reads).
  • WCU Boundary (1 KB!): Baseline writes were ~1% (~100 TPS). But exceeding 1.0 KB forced DynamoDB to charge 2 WCUs per write.
  • Multipliers (Tx & Global Tables): 2x Transactional write penalty + 3-region replication multiplied every write, doubling WCU burn across regions.
  • Batch Ingestion Wall: Tenant onboarding / bulk updates spiked to 300+ TPS, hitting per-partition WCU ceilings and causing severe throttling.
NoSQL Evolution & 4-Phase Protocol
  • Schema Minification: Mapping verbose names (relation➔r) pulls records under 1 KB (~950 bytes = 1 WCU), halving write burn.
  • Zero Direct Scans: Scanning DynamoDB directly would exhaust per-partition RCUs, immediately starving live enterprise authentication queries.
  • 4-Phase Rollout Strategy:
    1 Dual-Write app code (old + new)
    2 Backfill Migration Service in Go
    3 Cutover read/write to minified schema
    4 Cleanup pass for legacy attributes
  • Zero Customer Impact: Protect Fortune 500 auth SLAs and maintain zero downtime throughout a multi-week backfill run.

1. Point-in-Time Export to S3 & Schema Minification

Native DynamoDB export to S3 offloaded 100% of read traffic (0 live RCUs). The GoLang ETL engine mapped verbose attributes (relation➔r), pulling record size from 1.05KB to ~950 bytes (<1KB), halving WCU cost.

2. 1-Thread-Per-Partition & Strict 5% WCU Capping

Because each S3 export file corresponds to a single partition, we mapped 1 worker thread per partition file and strictly capped throughput to max 5% WCU per partition. 50 parallel Go workers mathematically guaranteed zero live throttling.

3. Production Dual-Writing & S3 State Checkpoints

Shipped Phase 1 dual-writing to live production. Checkpointed migration state in S3 metadata for deterministic resume during K8s pod recycles. Throttled conditional writes safely handled duplicate tuples as clean no-ops. Monitored in Datadog.

Reflections, Learnings & The Strategic Pivot

Production dual-write execution, the Aurora DSQL macro-pivot & Staff opportunity cost leadership
Part 2: Hindsight & Learnings
Production Execution & Technical Proof
  • 1KB WCU Boundary Optimization: Pulling payload under 1KB (~950 bytes) cut base WCU from 2 to 1, effectively doubling batch ingestion limits and projecting $30,000–$45,000/yr in AWS write savings.
  • Phase 1 Dual-Write Shipped Live: Pushed to production and successfully ran dual-writing on live traffic with zero auth latency impact or data drift.
  • S3 Snapshot (0 RCU) & 5% Cap: Offloaded read load to S3; 1 Go worker per partition file capped at 5% WCU mathematically guaranteed zero hot partition throttling across 50 workers.
  • S3 Checkpoint Storage: Kept state in S3 metadata, ensuring deterministic K8s pod crash recovery without DynamoDB pollution.
The Strategic Pivot & Staff Leadership
  • Macro-Shift to Aurora DSQL (The Plot Twist): Right after completing Phase 1 dual-write, the architecture board made a strategic pivot to move away from DynamoDB and adopt Distributed SQL (Aurora DSQL).
  • The Staff Call (Ruthless Prioritization): As migration lead, I made the call to halt the second half of the rollout. Pushing through to finish a DynamoDB-specific schema backfill for a datastore being deprecated would have wasted engineering capital.
  • Graceful Sunset & Capital Redeployment: Safely wound down pipelines, preserved audit logs, and pivoted team focus toward evaluating access patterns for the new Aurora DSQL engine.
  • Core Takeaway: Execution velocity is important, but architectural alignment is everything. Knowing when to pull the plug separates senior execution from Staff leadership.
